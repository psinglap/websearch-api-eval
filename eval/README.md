# Live web-search eval harness (You.com vs 5 rivals, 3 agent use cases)

> **Published results:** the [live evaluation](https://psinglap.github.io/websearch-api-eval/) compares four of these providers (You.com, Tavily, Exa and Parallel), run on Oct 8, 2026. The query set is in [`../reports/Agent queries.md`](../reports/Agent%20queries.md). API keys are never committed: copy `.env.example` to `.env` and add your own.

This harness compares six search APIs: **You.com, Tavily, Exa, Parallel, Firecrawl and Linkup**. Claude's built-in web search was dropped from the comparison; `providers/claude_native.py` is still on disk but no config uses it. It uses 30 agent-style search calls from `reports/Agent queries.md`:
- GTM G1–G10
- Insurance I1–I10
- Finance F1–F10

The harness is promptfoo (pinned **0.124.0**) with Python providers and assertions. All 12 metrics are defined in **[METRICS.md](METRICS.md)**.

**`answer_mode: offline` is the default (`config/settings.yaml`). It makes no Anthropic or OpenAI API calls.**
- **What a provider call does:** each provider only searches. Latency, normalization, raw JSON, dates, anomalies and search cost are all recorded, and the output is a compact JSON of the top results.
- **Assertions:** promptfoo runs only the checks that need no LLM. These are freshness, recall, URL validity of the returned results, content-in-one-call, latency budget, reliability and search cost.
- **Answers and grades:** Claude Code (the assistant, on your subscription) writes these afterwards from `./run.sh export <uc>`, following [grading/RUBRIC.md](grading/RUBRIC.md). The output goes into `grading/grades_<uc>.csv`, and `analysis/analyze.py` reads it to fill:
  - accuracy
  - correct-none
  - precision@5
  - citation support
  - token efficiency (approximate: tiktoken cl100k over the top-5 result content)
  - cost per correct (search cost only, no LLM)
- **Inclusion rule:** a provider is ranked in a use case only if ≥80% of its calls succeed and ≥80% return at least one result with a URL. Otherwise it is marked "excluded: insufficient evidence" with the reason, in both the scorecard and the charts.
- **Legacy path:** the old API path (Claude answers, plus LLM-graded assertions such as context-faithfulness) is still available. Set `answer_mode: api` in `config/settings.yaml` (or `ANSWER_MODE=api` in `.env`). Then run `.venv/bin/python tests/build_tests.py && .venv/bin/python config/make_configs.py`. It needs `ANTHROPIC_API_KEY`.

## Step by step

### 0. One-time setup (≈ 3 min)

```bash
cd eval
./run.sh setup --playwright      # uv venv (.venv, Python 3.12) + requirements + npm promptfoo 0.124.0 + Chromium; validates configs
cp .env.example .env             # then fill in the keys (never commit .env)
```

`.env` needs:
- **Search providers:** `YDC_API_KEY`, `TAVILY_API_KEY`, `EXA_API_KEY`, `PARALLEL_API_KEY`, `FIRECRAWL_API_KEY`, `LINKUP_API_KEY`.
- **SEC:** `SEC_USER_AGENT="Your Name you@domain"`. SEC EDGAR rejects anonymous clients, so set this.
- **Optional:**
  - `GITHUB_TOKEN` raises the search limit from 10 to 30 requests per minute.
  - `IA_ACCESS_KEY`/`IA_SECRET_KEY` turn on the authenticated Wayback SPN2 API, which is faster and more reliable than anonymous.
  - `ANTHROPIC_API_KEY` is needed only for `answer_mode: api`, and `OPENAI_API_KEY` only for the optional cross-check. Neither is needed by default.

### 1. Friction log while you sign up

Start a stopwatch and screen recording. As you go, log anything that happens:

```bash
.venv/bin/python friction/log.py tavily "first call" "401 with Bearer header" red 5 --category auth
.venv/bin/python friction/log.py note exa "free credits not shown in API response" --category billing/credits
```

Then fill in `friction/friction_summary.csv` (time to first call, signup steps, card, credits). See [friction/README.md](friction/README.md). During runs the harness also auto-logs every anomaly.

### 2. Smoke test (1 query × 6 providers, 1 repeat; cents)

```bash
./run.sh smoke
```

It writes `out/smoke_results_*.json` and raw provider JSON under `out/raw/smoke/`. Check that every provider returned results. If one failed, its 401/400 shows up in `friction_log.csv`.

### 3. For each use case (Insurance first, then Finance in market hours, then GTM)

```bash
./run.sh keys insurance     # pull open-API ground truth into ground_truth/*.json (+raw) and archive every source URL (Wayback)
```

**Answer keys.**
- Claude Code drafts `expected_answer`, `expect_none`, `tolerance`, `wayback_url` and `captured_at_utc` in `answer_keys.csv`. It works only from the archived official sources.
- **You review the drafts before the run.**
- A row left as `[FILL AT RUN TIME]` is exported with no key and reported as UNGRADED, never as wrong.

```bash
./run.sh run insurance      # evidence before (real-time QIDs) -> ground truth refresh -> promptfoo --repeat 3 --no-cache (search only) -> evidence after
./run.sh export insurance   # -> out/grading/insurance_to_grade.jsonl (+ grading/grades_insurance.csv template, if missing)
```

- **What the export holds:** one line per (qid, provider) for run 1. Each line has `upstream_task`, `query`, `needs_back`, the expected answer with its source and Wayback URL, and the top 5 normalized results (title, url, date, snippet, content ≤1500 chars).
- **Grading:** Claude Code answers each line and grades it into `grading/grades_insurance.csv` using [grading/RUBRIC.md](grading/RUBRIC.md):
  - accuracy: SimpleQA, with partial credit for list answers
  - correct-none: FreshQA strict
  - precision@5: TREC-style binary relevance per result
  - citation support
- Re-check the real-time keys (I1–I5, F1–F5, G1/G2/G7/G10) against the before/after captures in `evidence/evidence_log.csv`. If an answer changed during the run, fill `answer_changed_during_run`.
- `./run.sh run finance` also runs the **F1 You.com knowledge=core variant**.

### 4. Analysis, human check, viewer

```bash
./run.sh analyze            # out/{uc}_scorecard.csv, {uc}_per_query.csv, {uc}_paired_vs_youcom.csv, summary.md, charts/
./run.sh view               # promptfoo web UI (search results, latency, deterministic checks)
```

**Human check.**
- `analyze` writes a reproducible 20% random sample of the graded rows (seed 42) to `out/grading/<uc>_human_check.csv`.
- To review a row, fill `human_accuracy_0_2`, or set `human_agree` to y/n, and add notes if you want.
- Re-run `./run.sh analyze`. It reports the agreement rate in `summary.md` and keeps your entries.

### Optional: cross-check

`./run.sh crosscheck` is **optional and skipped by default** because it requires an OpenAI key (and an Anthropic key for our arm). Our SimpleQA grader text is identical to You.com's harness. It matches Tavily's except for formatting. The code stays in `crosscheck/`.

### Run order (summary)

`setup` → `smoke` → `keys <uc>` → (Claude Code drafts answer keys from archived official sources; you review) → `run <uc>` → `export <uc>` → (Claude Code grades) → `analyze` → `view`

## How latency is measured

- **Search providers:**
  - Timing is `time.perf_counter()` around the HTTP request only, from send to full response body.
  - Each provider uses one persistent `httpx.Client`, so connection reuse is the same for everyone.
  - Each promptfoo worker makes one discarded warm-up call first (`warmup_mode: search` in `config/settings.yaml`). Use `connect` to warm only the TLS connection without spending credits.
  - promptfoo keeps Python provider workers alive between calls (verified), so warm-up happens once per provider per run. One worker per provider means calls to the same provider never overlap.
  - The value goes into `metadata.search_latency_ms` and is returned as promptfoo `latencyMs`, so the viewer and the `latency` assertion show search time, not search plus LLM. Provider-reported latency is stored next to it (You.com `metadata.latency`, Tavily `response_time`, Exa `searchTime`).
- **Summary statistics:** p50 and p95 are computed over all 30 calls per provider per use case. Graded metrics use run 1 of each query. With 30 samples, p95 is roughly the second-worst value, so treat it as indicative.

## Fairness rules built in

- **Same inputs:** identical query string, 10 results, and full content where supported (You.com `extraction full_page`, Tavily `include_raw_content`, Exa `contents.text`, Firecrawl `scrapeOptions.markdown`; Parallel and Linkup return excerpts).
- **Date filter:** the freshness window is applied with each provider's own filter:
  - Real-time queries use the tightest filter each API offers: hours-based where the API takes a timestamp (Exa), otherwise `day` or today's date.
  - Week queries use `week` presets where they exist.
- **Domain hints:** sent only where an API supports them (`include_domains` and equivalents). A provider that ignores them is detected and auto-logged.
- **Answer step:** every provider gets the same inputs. The answerer sees `upstream_task` + `needs_back` + the top 5 results, must cite them, and may answer "NONE / not found".
  - Offline (default): Claude Code reads the export, where content is ≤1,500 chars per result, and cites `[r1]`..`[r5]`.
  - api mode: the shared prompt passes 2,000 chars per result and requires `[n]` citations.
- **Models:** the grader model and settings are fixed in `config/settings.yaml`.
- **Refusal fallbacks:** server-side refusal fallbacks are deliberately **off**, because a fallback would silently swap the answer model. The served model and stop_reason are recorded instead.

## Cost estimate (check `config/prices.yaml` before running)

**Per use case:** 6 providers × 30 calls.
- Search: at most ≈ $0.05 per call (Firecrawl Hobby is the most expensive).
- LLM: **$0 by default**. `answer_mode: offline` makes no API calls, and Claude Code answers and grades under your subscription. Cost per correct answer is therefore search cost only.
- `answer_mode: api` (legacy) adds Claude answer and grader calls, roughly $20–40 per use case at Opus 5.5 rates.

## Offline checks (no keys)

```bash
./run.sh test        # 44 pytest unit tests on FAKE fixtures (incl. export, grades loading, inclusion rule)
./run.sh fixtures    # full promptfoo run in EVAL_MOCK=1 mode (6 providers) + FAKE grades (tests/fixtures/grades/) -> out/fixture_charts/ (every title says "FIXTURE DATA – not results")
```

Mock mode uses fake `.invalid` URLs and text marked FIXTURE, and it never calls a paid API. It exists only to prove the pipeline end to end.

## Where things go
- **Raw provider JSON (per call):** `out/raw/{usecase}/{qid}/{provider}_{timestamp}.json`, with auth headers redacted.
- **Assertion details:** `out/assert_log.jsonl`. It holds dates, URL checks and recall hits.
- **Grading:** `out/grading/<uc>_to_grade.jsonl` (export), `grading/grades_<uc>.csv` (Claude Code grades), `out/grading/<uc>_human_check.csv` (20% sample for you).
- **Evidence:** `evidence/evidence_log.csv` plus `out/evidence/<phase>/<qid>/` (HTML and PNG).
- **Ground truth:** `ground_truth/{qid}.json` and `ground_truth/raw/`.
